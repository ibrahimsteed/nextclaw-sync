# 普通小文件短对照

基线 6521c7e。此工作树是计时专用版本，保留原四路下载、原同组屏障、四路写入、现有容量预留、条件读取和独占发布。采样覆盖一次 Android 首次 B，无 GIF 或其他附件。

## 现场清单

1. 固定计时包三附件及工具，复核 MuMu 和 Obsidian 1.15.1。用 fixture.mjs 生成 64 个 2–256 KiB 普通 Markdown 文件，和随附 fixture.json 的大小及 SHA256 逐项比对。发布到本轮专用隔离只读快照，派发前核对文件数、路径、大小、远端文件 ID 和强 ETag。测试前确认远端不包含其他普通文件。准备阶段不创建远端快照。
2. 新建独立应用存储空库，按已核验的 A→B 入口完成模式 A，核对两项基线文件及插件身份。B 前在初始文档启用既有原生只读范围门禁和日志，确认目标库、快照、空内容及插件版本。密码只用专用终端无回显输入。
3. 启动计时采证器并等独占 ready 回执，再点击 B 一次。文件标识是冻结夹具相对路径，记录器检查来源文档、单调时间、序号及路径白名单。示例命令：
   ```sh
   node tools/small-file-probe/collect.mjs CDP_PORT VAULT_NAME tools/small-file-probe/fixture.json /absolute/run/events.jsonl
   ```
4. 每条采样同步写入并 fsync。原件保留未配对 start。采满 64 条经核验的 checkpoint 读回即停止采样。硬停后的 JSONL 可导入 trace.mjs 的 summarize 重算，缺事件不补零。
5. 停用计时插件、清除并读回测试密码、退出采证、停止本轮 Obsidian 并核验 ADB/CDP/SSH 转发及防睡收割。保留测试库、冻结快照与证据。若早已进入自动重载，只按同一测试库及本轮进程身份收尾。

## 计时与判定

版本查询和 GET 记录 Promise 启动至回执，原生请求记录用于交叉核对。download-ready 位于下载及下载后版本核验通过之后。下载就绪至同组最后一项成功或失败是同组等待。最后一项就绪至组释放单列，包含上一组写入及调度等待。组释放至受保护写入开始包括检查、暂存及写队列等待。受保护写入单列，含独占创建及其保护等待。记录 IndexedDB 写事务创建、oncomplete 和所需读事务，以及已核对内容、代次和提交 ID 的成功读回。此计时不等同于所有 IndexedDB 后台 I/O。

同一次运行做逐组快慢同伴对照，报告总组数及完成样本数，分开各阶段的中位数、尾部和累计等待。保留各文件原始区间，避免并行阶段相加。至少 8 个完整组才作方向判断。若至少半数完整组出现快文件的同组等待超过 100 ms，且同组等待占这些文件下载就绪到开始写入的时间至少一半，则认定值得另建调度候选。该门槛只用于选择下一项工程试验，不是产品性能验收。若观察不足则结论为缺证。只有独立数据指向 IndexedDB 事务为主要瓶颈，才讨论批提交。

## 预算与停止

单次总预算 20 分钟。夹具上线及只读核验 4 分钟，测试应用/空库/模式 A 6 分钟，B 准入与交互凭据 3 分钟，B 点击后采样最多 3 分钟，收尾 4 分钟。超时、身份不符、快照变化、门禁阻断、采证中断、序号缺失、提前换代、同步失败、出现目标占用或远端写入意图即保全停止。一次点击，不重发。采证器不代替外层阶段截止，人工或控制端负责停用与收尾。

短对照只定位瓶颈，10 分钟 Goal 仍以完整空库 A→B 收敛、自动重载、指定笔记可打开和同轮独立终检裁定。保留 6521c7e MuMu 19 分 05 秒首次核实可用及独立终检。第二项 8141b5b、85 项离线回归和原 GIF 探针留存，附件容量仍待 Android 现场。
